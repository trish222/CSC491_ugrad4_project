# CSC 491 Shrinking-Code Project — Requirements

**Status:** Approved by lecturer  
**Client:** A software project manager preparing staffing and effort estimates for new projects.  
**Dataset:** MOOT `process/nasa93dem.csv`  
**Project goal:** Use past software projects to estimate effort and defects, explain risks, and compare planning options.

| Step | Skill | What the project manager wants to ask |
| --- | --- | --- |
| 1 | remember | Which past projects delivered a lot of software with relatively little effort and few defects? |
| 1 | remember | What were the typical effort and defect counts for projects similar to the one I'm planning? |
| 2 | guess | Roughly how many person-months should I budget for this proposal? |
| 2 | guess | How many defects should my team plan to handle on this project? |
| 3 | certify | Have projects with stronger analyst capability actually taken less effort among otherwise similar projects? |
| 3 | certify | Do similar projects with stronger tool support have meaningfully fewer defects, or do the records show too much variation to tell? |
| 4 | flow | As each proposal arrives, which ones look likely to exceed our effort budget? |
| 4 | flow | As completed projects come in, can I see how many met both our effort and defect targets so far? |
| 5 | blame | What stands out about projects that took much more effort than their closest peers? |
| 5 | blame | Which project conditions show up most often when defect counts are unusually high? |
| 6 | justify | Which past projects back up the effort estimate you gave me? |
| 6 | justify | Why did these two proposals get different risk ratings even though they look similar? |
| 7 | choose | If I can examine only a few past project plans in detail, which should I review first for low effort and few defects? |
| 7 | choose | Which planning option should I review first when reducing defects matters more than saving effort? |
| 8 | fix | What single change within my control could bring this proposal closer to our effort budget? |
| 8 | fix | If our staffing stays fixed, what is the smallest change to the plan that might bring defects under our target? |
| 9 | spot | Which incoming proposals are so unlike past projects that I should double-check their estimates? |
| 9 | spot | Which completed project records look unusual enough for me to check for a data-entry error? |
| 10 | race | On past projects set aside for testing, does your effort estimate beat using the same typical effort for every project? |
| 10 | race | If two ways of picking plans get the same number of reviews, which one finds more options that meet both targets? |

The historical records support comparisons and planning estimates. Suggested changes are options to investigate. Their real-world effects would need separate validation.
